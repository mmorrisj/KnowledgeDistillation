Fine-tuning, distillation and LoRA are all small changes to one training process. This lesson gives you that process, with only as much detail as the rest of the course needs.

## From text to probabilities

A transformer never sees letters or words. It sees <mark>tokens</mark>: pieces of text, each mapped to a number. "Distillation" might be split into three tokens; "cat" is usually one.

Given some tokens, the model produces one score for every token in its vocabulary, often more than 100,000 of them. These raw scores are called <mark>logits</mark>. A function called softmax turns the logits into probabilities that add up to 100%.

To write text, a model picks a token from this list, adds it to the input, and repeats. Everything a language model produces comes from this one step, done over and over.

Keep this picture in mind. The full list of probabilities, not just the top answer, is what a student learns from in Module 3.

## How the weights are learned

A model's behavior is set by its <mark>weights</mark>: millions or billions of numbers. Training adjusts them with the same loop every time:

1. Show the model an input.
2. Let it predict.
3. Compare the prediction with a <mark>target</mark>, the answer you wanted.
4. Nudge every weight slightly in the direction that would have made the prediction closer to the target.

The measure of the gap in step 3 is called the loss. For language models it is almost always cross-entropy, which is small when the model gave the target a high probability and large when it did not.

## What makes transformers different

Classical models, such as logistic regression or gradient-boosted trees, also learn by shrinking a loss. The difference is where the knowledge comes from.

<div class="table-wrap">

| | Classical model | Transformer |
|---|---|---|
| Starting point | Knows nothing | Already pretrained on a very large amount of text |
| Input | Features a person designed | Raw text, as tokens |
| Labels needed | Every example, for each task | None for pretraining; a small set for your task |
| One model per task? | Yes, trained from scratch | One pretrained model, adapted to many tasks |

</div>

The key idea is <mark>pretraining</mark>. Text supplies its own targets: hide the next token and ask the model to predict it. Nobody has to label anything, so a model can be trained on billions of words. To predict the next token well, it has to pick up grammar, facts and a good deal of reasoning along the way.

That gives training two stages. Pretraining is done once, at great expense, by a large lab. Adapting the result to your task is cheap, and it is the stage this course is about.

## Two shapes of model

You will use both of these as students.

- **Encoder models** (BERT, ModernBERT) read the whole input at once and produce a summary of it. Add a small layer on top and they classify or extract. They are small and fast.
- **Decoder models** (GPT, Qwen, Llama) read left to right and predict the next token. They generate text, which lets them do almost any task, at a higher cost.

A vision transformer is built from the same blocks as a text transformer, so LoRA attaches to it the same way: thin trainable matrices beside the frozen attention weights. Two details differ, and both are worth knowing.

## The output layer is new

In Module 5 the generative student wrote its answer as text, using the output layer it already had. An image classifier is different. The pretrained model's output layer was built for whatever classes it was pretrained on. For 37 pet breeds you replace it with a fresh layer of 37 outputs, and that layer starts with random weights.

  It learns badly. The adapters can reshape what the model passes upward, but the last step is still a random layer that nothing is allowed to fix. The new output layer has to be trained in full, alongside the adapters. It is small, so this costs almost nothing. The course code does this for you; if you set LoRA up yourself, it is the mistake to look for first.
</PredictReveal>

## Layer names differ between libraries

LoRA is attached to layers by name, and vision models do not always use the names text models do. Even one model can have different layer names in different versions of a library. The course code looks the names up from the model you give it. If you configure LoRA by hand and get an error saying no layers were matched, print the model's layer names and use what you see.

## When it is worth it

The memory argument from lesson 5.1 is weaker here. Vision students of the sizes used for classification are small by language-model standards: 86 million weights can be fully fine-tuned on the lab's GPU with room to spare. LoRA is not needed to make this model fit.

It still earns its place in three situations:

- **Many tasks, one base model.** A few megabytes of adapter per task in place of a full copy each.
- **Very little data.** Freezing most of the model limits how far a handful of examples can pull it, which can reduce overfitting.
- **Much larger vision models.** The biggest image-and-text models have billions of weights, and there the memory argument returns in full.

The lab runs LoRA on the larger student so that you can compare it with the fully fine-tuned small one. That comparison mixes two changes, a bigger model and a different way of training it, and the lab lesson says how to read it.

## Beyond classification

You will meet LoRA most often in vision in a setting this course does not cover: adapting image generators to a style or a subject. The mechanism is exactly what you learned in Module 5, attached to a different kind of model. Nothing about it will be unfamiliar.

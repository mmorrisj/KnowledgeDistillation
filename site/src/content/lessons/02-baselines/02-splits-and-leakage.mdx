A score is only worth something if the model has never seen the questions. When information from the test set reaches the model during training, the score goes up and the model does not get better. That is <mark>leakage</mark>, and distillation adds new ways for it to happen.

## Four piles, four jobs

- **Gold training set.** The labelled messages the student learns from.
- **Gold validation set.** Labelled messages for decisions: how long to train, which prompt wording to use, which settings to keep.
- **Unlabelled pool.** Messages the teacher will label. This is where the teacher's knowledge enters.
- **Test set.** Scored once for each finished model. It answers one question: how good is this model on messages it has never influenced?

The rule that keeps the test set honest is simple to state and easy to break: **never make a decision based on a test score.** Every time you look at a test score and then change something, a little of the test set leaks into your choices.

## How leaks happen

**The same message is in training and test.** Public datasets contain repeats and near-repeats. The course code compares messages, ignoring case and spacing, and removes any training message that also appears in the test set.

**Decisions are tuned on the test set.** You try five prompts for the teacher and keep the one with the best test score. That prompt is now fitted to the test set. Choose it on the validation set.

**The teacher sees test messages.** If you show the teacher example messages in its prompt, they must come from the gold training set. If you ask the teacher to write new messages "like these", the samples must not come from the test set.

**The pool's true labels get used.** In this course the pool's real labels are stored so that you can measure the teacher's mistakes later. Training on them would turn the scarce-label scenario into the full-label one.

**The teacher saw the dataset before you did.** A large model may have read a public dataset, test set included, during its own pretraining. You cannot undo this. It is one reason a teacher's score on a public benchmark can flatter it, and why results on your own private data are the ones to trust.

## A habit worth keeping

Write the test score down once per finished model, with the date, and move on. If you find yourself scoring on the test set several times a day, you are using it as a validation set.

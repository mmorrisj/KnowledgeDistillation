LoRA adds a handful of settings to the ones you already know. Most of the time the defaults are fine, and the useful skill is knowing which one to change when they are not.

## The settings and where to start

<div class="table-wrap">

| Setting | What it controls | Starting value | Change it when |
|---|---|---|---|
| Rank | How much the update can express | 16 | The task is very different from what the model already does: go higher. The task is simple or data is scarce: go lower |
| Alpha | How strongly the update is applied; the update is scaled by alpha ÷ rank | Twice the rank | Rarely. Keep the ratio fixed when you change the rank |
| Target layers | Which weight matrices get adapters | The attention matrices | Results trail full fine-tuning: add the feed-forward matrices too |
| Dropout | Randomly ignores part of the update while training, to limit overfitting | 0.05 | Training data is small and validation scores fall while training loss keeps dropping: raise it |
| Learning rate | Step size | About 2e-4 | Loss jumps around: lower it. Loss barely moves: raise it |

</div>

## The learning rate is the one that surprises people

Full fine-tuning of a transformer typically uses a learning rate around 2e-5. LoRA wants roughly ten times that. The adapters start from nothing and have to learn the whole change, while the frozen weights keep the model stable. Using a full fine-tuning learning rate with LoRA is the most common reason a first LoRA run "doesn't learn".

## Rank is not a quality dial

A higher rank lets the update express more, and it is tempting to turn it up. Past the point the task needs, extra rank adds weights without adding accuracy, and with little data it can overfit. For a narrow task such as sorting messages into fixed types, low ranks usually do as well as high ones. You will test this in the lab.

## When LoRA falls short

Sometimes a LoRA-trained student scores a little below the same student fully fine-tuned. Try, in this order:

1. Check the learning rate.
2. Add adapters to more layers.
3. Raise the rank.
4. If the model is small enough to fully fine-tune on your card, do that. LoRA exists for when you cannot.

## Tune on validation, and tune little

Every setting is chosen the way temperature and prompts were: compare on the validation set, score the winner once on the test set. With a few hundred validation messages, differences of a point or two between settings are noise. Change one thing at a time, and stop when the changes stop mattering.

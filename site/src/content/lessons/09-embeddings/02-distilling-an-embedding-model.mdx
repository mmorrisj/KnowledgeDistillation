In Module 3 the student matched the teacher's probabilities over classes. In Module 6 it matched probabilities over tokens. An embedding model has neither. So what is there to match?

## What the teacher knows

The teacher's knowledge is in the arrangement: which texts it places close together and which far apart. A good student is one that arranges texts the same way. There are two ways to ask for that.

## Option one: match the vectors

Train the student so that its embedding of each text is close to the teacher's embedding of the same text.

This runs into a practical problem at once. The teacher produces 1,024 numbers and the student 384, so the two cannot be compared directly. The usual fix is to add a small extra layer to the student that stretches its 384 numbers to 1,024 for training.

What you get is a student that lives in the teacher's space. Its embeddings can be compared with the teacher's, which is useful if you want to keep an existing index and only speed up queries. What you give up is the shorter list: the output is back to 1,024 numbers.

## Option two: match the similarities

Do not compare vectors at all. Take a batch of texts, compute how similar each pair is according to the teacher, and train the student so that its similarities for the same pairs agree.

A batch of 128 texts contains more than 8,000 pairs, so each training step carries a great deal of signal. It is the embedding counterpart of dark knowledge: the teacher says not just that two messages are related, but how closely, for every pair.

<div class="table-wrap">

| | Match the vectors | Match the similarities |
|---|---|---|
| Different lengths | Needs an extra layer | No problem |
| Student's output length | The teacher's | Its own, shorter |
| Compatible with the teacher's index | Yes | No; the collection is embedded again |
| Best when | You must keep an existing index | You want the full saving in storage and speed |

</div>

## No labels anywhere

Look at what this training needs: texts, and the teacher's embeddings of them. No one has to say what any text is about. Any pile of text from your domain will do, which makes this the easiest kind of distillation to get data for.

```python
from kd_course.embeddings import (
    EMBED_STUDENT_ID, EMBED_TEACHER_ID,
    embed_texts, load_embedder, train_embedding_student)

teacher, teacher_tokenizer = load_embedder(EMBED_TEACHER_ID)
teacher_vectors = embed_texts(teacher, teacher_tokenizer, pool_texts)      # 1

student, student_tokenizer = load_embedder(EMBED_STUDENT_ID)
train_embedding_student(student, student_tokenizer,
                        pool_texts, teacher_vectors)                       # 2, 3
```

## The baseline is strong

In the earlier modules the untrained student was weak: a few labels, or no training at all. Here the student is a published embedding model that already works well on general text. The honest question is not whether it works, but whether distilling it on your own domain makes it meaningfully better there. On some domains the gain is large. On others, where the general-purpose student already does well, it is small. The lab measures it.

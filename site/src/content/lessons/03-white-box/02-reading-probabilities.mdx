The teacher in this course is a text-generation model. It was never built to output 77 numbers, one per type. This lesson shows how to get them anyway.

## From next-token probabilities to type probabilities

Recall from Module 1 that a language model gives a probability to every possible next token. A type name such as `card_arrival` is a short run of tokens. The probability that the model would write that whole name is the product of the probabilities of its tokens, each given the ones before.

So for one message:

1. Give the model the same prompt as in Module 2: the instructions, the list of types, and the message.
2. For each of the 77 type names, work out how likely the model is to write exactly that name next.
3. Rescale the 77 results so they add up to 100%.

No text is generated. The model is only asked, 77 times, "how likely is this continuation?"

## Making it fast

Done naively, that is 77 passes through a large model for every message, each re-reading a prompt of several hundred tokens. Two savings make it practical.

The first saving reuses work the model has already done. A transformer can keep its internal state for text it has read and carry on from there, so the long shared part of the prompt is read once for the whole dataset.

The second saving is the last step. Scoring is the slow part of white-box distillation, and its output does not depend on anything about the student. Compute it once, save it, and every later experiment with temperature, loss weights or student size reads the saved file. It also means the teacher and the student never need to be on the GPU at the same time.

## A size note for later

With 77 types, saving every probability for every message costs almost nothing. That stops being true when the student is learning to generate text: there the teacher has a probability for each of more than 100,000 tokens at every position. Module 6 deals with that by keeping only the top few.

## Do teacher and student need the same tokenizer?

It depends on what the probabilities are over.

- **Over types**, as in this module: no. The teacher's 77 numbers and the student's 77 numbers line up by type, whatever tokens each model used to read the message. That is why a Qwen teacher can train a ModernBERT student here.
- **Over next tokens**, as in Module 6: yes. The student must predict the same tokens the teacher did, so both must split text the same way. This is why the generation modules use a teacher and a student from one model family.

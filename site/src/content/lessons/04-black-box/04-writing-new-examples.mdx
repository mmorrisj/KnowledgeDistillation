Labelling needs a pool of unlabelled messages. Sometimes there isn't one: the product is new, or the data cannot leave a secure system. A text-only teacher can do something a white-box teacher's probabilities cannot. It can write the examples.

## How it works

For each type, you ask the teacher to write a batch of new messages a customer might send, and you show it a couple of real ones so it knows what you mean. Each generated message comes with its label already attached: the type you asked for.

This is often called <mark>synthetic data</mark>.

## What goes wrong

Generated data fails in ways labelled data does not.

**It all sounds the same.** Ask for 20 messages and many start the same way, run to the same length and use the same polite tone. Real customers misspell, ramble and write three words. A student trained on tidy messages meets untidy ones in production.

**It repeats itself.** The same message, or nearly the same, comes back many times, within a batch and across batches.

**It drifts off type.** Asked for one type, the teacher sometimes writes a message that belongs to a neighboring type. The label says one thing and the message says another.

**It leaks.** If the example messages you show the teacher come from the test set, the teacher will write variations of test messages into your training data.

## The guards

<div class="table-wrap">

| Problem | Guard |
|---|---|
| Sameness | Ask for variety in wording, length and tone. Show different real examples in each request |
| Repeats | Remove duplicates, ignoring case and spacing |
| Off-type messages | Round-trip check: ask the teacher, in a fresh request, to classify each message it wrote. Keep it only if the answer matches the type you asked for |
| Leaks | Show only gold training messages as examples. Remove any generated message that matches a validation or test message |

</div>

## Always score on real data

<PredictReveal
  client:load
  id="synthetic-test"
  prompt="A student trained only on generated messages scores 95% on a test set that was also generated by the same teacher. What does that tell you about how it will do on real customer messages?"
  options={["It will score about 95%", "Very little", "It will score higher, because real messages are easier"]}
>
  Very little. The student and the test set share the teacher's habits, so the score measures how well the student learned those habits. Only real messages can tell you how it handles real messages. Keep a test set of real data, however small, and never generate one.
</PredictReveal>

For the same reason, generated data works best mixed with real data. Even a few real examples per type keep the student anchored to how people actually write.

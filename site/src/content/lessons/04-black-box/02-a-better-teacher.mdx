A student can only learn what its teacher shows it. So before labelling anything in bulk, get the best answers you can out of the model you have. The prompt is the cheapest place to look.

## Three changes that usually help

**Show examples.** The Module 2 prompt gave the teacher a list of 77 type names and nothing else. Names such as `card_arrival` and `card_delivery_estimate` are easy to confuse without seeing what each looks like. Adding one or two real messages for each type, with its type, often lifts accuracy more than anything else. This is called a few-shot prompt.

The examples must come from the **gold training set**. Validation and test messages stay out of the prompt, for the reasons in lesson 2.2.

**Explain the confusing types.** If the per-type scores from Module 2 show two types being mixed up, add a sentence to the prompt saying how they differ.

**Tighten the format.** If many replies are unusable, the instructions are not clear enough about what to return. State it plainly: one type, copied exactly from the list, nothing else.

## Choose on the validation set

Each change gives you a new prompt. Score each one on the validation set and keep the best. The test set is not involved: it scores the finished student, once.

Keep a note of what you tried and what each scored. With only a few hundred validation messages, small differences between prompts are inside the margin of error. Prefer the simpler, shorter prompt unless the longer one is clearly ahead.

With a local teacher you pay in GPU time instead of money, and the same scaling applies: a prompt six times longer takes several times longer to run.

Some APIs reduce the price of a prompt prefix that repeats across requests. If yours does, put the fixed part first (instructions, types, examples) and the message last. That is the same idea you used in Module 3, where the shared part of the prompt was read once.

## When the prompt is not enough

If the best prompt still leaves the teacher level with the baseline or behind it, you have three options: a larger or stronger teacher, more human labels, or accepting the baseline. Knowing that before a bulk labelling run is the purpose of the check.
